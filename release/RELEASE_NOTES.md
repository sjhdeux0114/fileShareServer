# FileShare v0.4.0

아이폰에서 사진·영상을 올릴 때 조각마다 멈추거나 파일 사이에 오래 기다리던 문제를 줄이기 위해 업로드 전송 엔진을 다시 작성했습니다. 수정본에서 사용자가 실물 아이폰 업로드 정상 동작을 확인했습니다.

## 변경 사항

- fetch POST 기반 1MiB 분할 전송. 정상 전송 중 주기적인 상태 조회와 대기 시간을 제거하고 서버 응답을 받으면 다음 조각을 바로 보냅니다.
- 8MiB 이하 사진은 한 번 읽은 데이터를 재사용합니다. 큰 영상은 최대 8MiB 읽기 버퍼를 사용합니다.
- 일시적인 연결 오류·응답 유실 시 서버 저장 위치를 확인하고 최대 6회 자동 복구합니다. 일시정지는 파일 준비와 전송 대기에도 적용됩니다.
- 임시 조각마다 수행하던 디스크 동기화를 제거했습니다. 최종 파일은 디스크 동기화가 성공해야 전송 완료로 표시합니다.
- 완료 항목에 앱의 파일 준비 시간과 전송 시간을 표시합니다. 서버 PC 전용 업로드 진단 기록을 추가했습니다.
- 기존 업로드 API와 미완료 전송 정보는 호환됩니다. 파일 탐색기·로그인·공유 폴더 설정은 유지됩니다.

## 업데이트

기존 서버를 트레이에서 종료하고 실행 파일을 교체하세요. **FileShare.ini와 data 폴더를 유지**하면 설정과 미완료 전송을 계속 사용합니다. 자동 시작을 켰다면 EXE 경로를 유지하세요. 휴대폰 페이지를 새로고침하여 **v0.4.0** 표시를 확인하세요.

Windows x64/ARM64 단독 EXE와 ZIP, macOS ARM64/x64 패키지, 소스 ZIP, SHA-256 체크섬을 제공합니다.

## 검증과 남은 제한

- Windows x64에서 Go 테스트·vet 및 HTTP/전송 테스트 23개 통과. 64MiB 실제 업로드의 응답 유실 복구와 최종 SHA-256 일치, 4.6MiB 사진 전송, 중단된 조각 롤백, 준비 중 일시정지를 검증했습니다.
- 개발 중 PC 브라우저에서 사진 여러 개와 32MiB 파일의 업로드 완료를 확인했습니다. 사용자가 실물 아이폰 업로드 성공을 확인했으며, 모든 iOS 버전·환경에 대한 검증을 의미하지 않습니다.
- **사진첩에서 확인 후 선택창이 늦게 닫히고 추가 선택이 가능한 현상은 해결되지 않았습니다.** 파일이 웹페이지로 전달되기 전 iOS/WebKit 처리 구간입니다. 기기 내 사진의 형식 변환도 대기 원인이 될 수 있어 iCloud 문제로 단정할 수 없습니다. [관련 WebKit 보고](https://bugs.webkit.org/show_bug.cgi?id=325067)
- 이번 릴리스에서 Wi-Fi 다운로드 속도 개선을 주장하지 않습니다. 사용자의 다른 다운로드가 진행 중이어서 실기기 속도 재측정은 남아 있습니다.
- 전송 도중 전원 차단·OS 장애 시 임시 조각의 보존은 보장하지 않습니다. 포함된 21GiB 테스트 기록은 이전 전송 엔진의 결과이며 0.4.0에서 다시 수행한 결과가 아닙니다.
- Windows ARM64 및 macOS 패키지는 크로스 컴파일했습니다. 코드 서명·Apple 공증은 하지 않았습니다.
