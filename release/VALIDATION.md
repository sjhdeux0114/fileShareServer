# FileShare 0.4.0 검증

검증일: 2026-11-03 (Asia/Seoul).

## 0.4.0 릴리스 검증

- Windows x64, Go 1.27.3: go test ./... 및 go vet ./... 통과.
- 새 Windows GUI 실행 파일을 대상으로 Node HTTP/전송 테스트 **23개** 통과.
- 64MiB 실제 전송 중 조각·완료 응답 유실 복구와 다운로드 SHA-256 일치, 4.6MiB 사진의 새 POST 조각 전송, 재시작 후 재개, 중단된 요청의 15초 유휴 제한·롤백 검증.
- 정상 전송에서 상태 폴링·인위적인 대기 없이 여러 파일 완료, 타임아웃 후 위치 복구, 최대 6회 재시도, 영구 오류 중단, 일시정지·재개 검증.
- 작은 사진 한 번 읽기, 큰 영상 최대 8MiB 읽기, 파일 준비 중 취소, 읽기 오류 처리, 기존 파일 지문 호환성 검증.
- 개발 중 PC 브라우저에서 4.6MiB/6.2MiB 사진과 32MiB 파일 업로드 완료 및 저장된 파일의 SHA-256 일치를 확인했습니다. 사용자가 실물 아이폰 업로드 정상 동작을 확인했습니다.
- iOS 사진 선택창의 확인 후 닫힘 지연은 해결하지 못했습니다. 웹페이지가 파일을 받기 전의 동작으로, 이번 업로드 엔진 검증 범위와 구분합니다.
- 실물 아이폰 다운로드 속도 재측정은 남아 있습니다. 다른 다운로드와 경쟁하지 않는 Wi-Fi 성능을 이번 릴리스에서 보장하지 않습니다.
- Windows ARM64와 macOS ARM64/x64는 크로스 컴파일 배포이며 실제 기기 실행을 여기서 검증하지 않았습니다.
- 아래의 21GiB 기록과 기존 CI 링크는 **이전 버전 검증 기록**입니다. 0.4.0에서 21GiB 시험을 다시 수행하지 않았습니다.

## 이전 버전 검증 기록 (0.3.0 이하)


검증일: 2026-11-02 (Asia/Seoul). 최종 서버: Go 네이티브, Electron/Node 런타임 없음.

## 자동 테스트

- Go 단위 테스트: 경로 탈출·심볼릭 링크 차단, 원격 설정 변경 금지, 토큰 변조·키 변경 무효화.
- HTTP 통합 테스트 8개: 로그인/시도 제한/CSRF/로그아웃, 한글·이모지 파일, 재시작 후 이어 올리기, 잘못된 offset/Range, 빈 파일, 동명 파일, 업로드 크기 한도, 중단된 조각 롤백.
- 비밀번호 변경 후 이전 로그인 무효화, 비밀번호 평문 미보관, 새 쿠키로 서버 재시작 후 자동 로그인.
- 폴더 생성·복사·이동·이름 변경·영구 삭제, 충돌 거부, 루트 삭제 금지, 경로 탈출 차단, ZIP 내용 확인, 지정 하위 폴더 업로드, 공유 폴더 변경.
- Go `go vet ./...` 검사.

## 실제 대용량 전송

`large-file-test.json`에 기계 판독 가능한 결과를 보관합니다.

- 실제 데이터: **22,548,578,427바이트 (21GiB + 123바이트)**.
- 16MiB 조각으로 전량 업로드하고 실제 디스크에 기록.
- 5GiB에서 네이티브 서버 프로세스 종료·재시작 후 같은 offset에서 재개.
- 완성 파일을 전량 다운로드하여 SHA-256 일치 확인.
- SHA-256: `d8e93f2364176a5cc3a1c1b68a5d2ea191091ca0e9c2d5b94aac1f74d6cc7f6d`.
- Windows 로컬 루프백 테스트 전체 약 199초. 실제 Wi-Fi 속도를 의미하지 않습니다.
- 서버 PeakWorkingSet 샘플 최대 약 **15MiB**. 업로드 진행 중 1GiB마다 Windows 프로세스 누적 피크를 수집했습니다. 테스트 클라이언트 메모리는 별도 기록했습니다.

## 플랫폼과 제한

- Windows x64에서 네이티브 실행·HTTP 통합·대용량 왕복 검증.
- Windows ARM64, macOS ARM64/x64는 크로스 컴파일 패키지를 제공합니다.
- GitHub Actions **Windows/macOS/Linux 모두 성공**: [실행 결과](https://github.com/sjhdeux0114/fileShareServer/actions/runs/41445811755). Go 단위 테스트·vet·네이티브 빌드·HTTP 통합 테스트 8개를 각 OS에서 통과했습니다.
- Windows x64 ZIP을 실제로 풀어 포함된 배포용 실행 파일로 HTTP 통합 테스트 8개를 다시 통과했습니다. macOS tar.gz의 실행 파일·실행 스크립트 0755 권한도 확인했습니다.
- 데스크톱 브라우저: 한글 파일과 33MiB 파일 다중 업로드, 사진 버튼으로 하위 폴더 업로드, 새 폴더 생성·탐색, 이름 변경, 폴더 간 복사, 한글 파일 다운로드 내용 일치, 80×80 썸네일 로드, 서버 재시작 후 자동 로그인 확인.
- 390px 모바일 뷰포트에서 가로 넘침 없음 확인. 스크롤바를 제외한 실제 문서 폭 375px과 scrollWidth가 일치했습니다. 스크린샷은 `release/screenshots`에 보관합니다. 모바일 폭 검증은 실제 iOS Safari나 Android Chrome 검증을 대신하지 않습니다.
- **실물 아이폰·안드로이드의 사진/파일 선택기, 20GB 영상 업로드, 사진 앱 저장은 직접 검증하지 못했습니다.** 표준 파일 선택/Blob.slice/다운로드 및 Safari 공유 흐름을 지원하도록 구현했습니다.
- Apple 공증/Windows 코드 서명은 하지 않았습니다. 실제 공유기·방화벽 환경의 휴대폰 연결은 확인하지 못했습니다.

## INI·트레이·이름 변경 업데이트

- INI 경로/포트/인증 정보 왕복, 평문 비밀번호 해시 전환, 최초 PC 설정과 원격 초기 접근 제한 테스트 통과.
- 대소문자 변경과 충돌 보호, 짧은 읽기 잠금 대기, 실제 Windows 삭제 공유 권한 없는 파일 핸들 해제 후 이름 변경 재시도 테스트 통과.
- Windows GUI 서브시스템으로 빌드하여 콘솔 없이 실행. 네이티브 트레이 등록 성공 및 폴더 선택 대화상자 표시 확인. 네이티브 메뉴 클릭과 선택 완료는 자동 UI 환경 제약으로 직접 검증하지 못함.
- 위 21GiB 측정은 트레이 추가 전 동일 전송 엔진의 결과이며 트레이 포함 메모리 측정값이 아님.

0.3.0은 위 INI·트레이·이름 변경 수정본에 버전을 부여한 릴리스입니다. 21GiB 전송 기록은 0.1 개발 중 수행한 전송 엔진 검증입니다.

## 0.3.0 모바일 전송과 설정

- 64MiB 실제 데이터에 약 10MiB 간격의 연결 실패/조각 저장 후 응답 유실/완료 응답 유실을 주입하여 자동 복구, 최종 다운로드 SHA-256 일치 확인.
- 연결 복구 중 사용자 일시정지, 디스크 부족 등 영구 오류 재시도 금지, 지속적인 연결 실패 시 12회 한도 검증.
- 비밀번호 4자 저장 및 로그인 성공, 3자 거부. INI 자동 시작 값 왕복.
- Windows 레지스트리 API로 임시 비-Run 키에 경로 등록·공백/한글 경로 인용·해제를 검증. 사용자 실제 자동 시작 설정을 테스트로 변경하지 않음. 재부팅 검증은 수행하지 않음.
- 실물 iPhone Safari 재현 확인은 불가. 네이티브 사진 선택기 변환/다운로드 대기는 웹 코드 제어 범위 밖임.

- 데스크톱 브라우저에서 4자리 로그인, 64MiB 업로드 완료, 사진 버튼으로 PNG 10개 선택·자동 완료, JavaScript 오류 없음 확인. 이는 실제 iOS 선택기 검증을 대신하지 않습니다.
