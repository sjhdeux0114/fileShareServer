# FileShare 0.1.0

Windows·macOS PC의 폴더 하나를 공유하고, 같은 Wi-Fi의 iPhone·Android 브라우저에서 파일을 주고받는 가벼운 파일 서버입니다.

**Go 네이티브 단일 실행 파일**에 웹 화면이 포함됩니다. Electron, Node.js, Python 설치와 런타임 의존성이 없습니다. 파일은 내 PC에 저장됩니다.

## 실행

1. [v0.1.0 다운로드](https://github.com/sjhdeux0114/fileShareServer/releases/tag/v0.1.0)에서 PC용 패키지를 받아 **전체 압축을 풉니다**.

| PC | 패키지 |
|---|---|
| Windows Intel/AMD | `FileShare-0.1.0-windows-x64.zip` |
| Windows ARM | `FileShare-0.1.0-windows-arm64.zip` |
| Mac Apple Silicon | `FileShare-0.1.0-macos-arm64.tar.gz` |
| Mac Intel | `FileShare-0.1.0-macos-x64.tar.gz` |

2. Windows: **`FileShare.exe`를 더블클릭**하세요. 릴리스의 단독 `.exe`도 바로 실행할 수 있습니다. 콘솔 창 없이 트레이에 표시됩니다. Mac은 `start-macos.command`를 실행하고 서버를 유지하세요.
3. 첫 실행 시 PC 설정 화면이 자동으로 열립니다. **폴더 선택**으로 공유 폴더를 지정하고 접속 비밀번호(8자 이상)와 포트를 저장하세요.
4. 설정 화면에 표시되는 휴대폰 접속 주소를 같은 Wi-Fi의 iPhone·Android 브라우저에 입력하세요.
5. 다음 실행부터 저장된 INI 설정으로 서버가 바로 시작됩니다. Windows 트레이 아이콘 우클릭 → **설정**에서 변경하고 **종료**로 서버를 끕니다. 아이콘 더블클릭도 설정을 엽니다. 트레이가 숨겨져 있으면 작업 표시줄의 숨겨진 아이콘을 확인하세요.

비밀번호는 해시로 저장됩니다. 브라우저에는 비밀번호 대신 서명된 HttpOnly 로그인 쿠키를 30일간 저장하여 서버 재시작 후에도 자동 접속됩니다. 시크릿 모드·쿠키 삭제·다른 브라우저·IP 변경 시 다시 로그인해야 합니다. 비밀번호를 바꾸면 다른 기기의 기존 로그인은 해제됩니다. 설정은 **서버 PC에서 localhost 또는 127.0.0.1로 접속했을 때만** 변경할 수 있습니다.

첫 실행 시 Windows 방화벽에서 신뢰하는 **개인 네트워크**의 FileShare 접근을 허용해야 휴대폰이 연결됩니다. Mac도 로컬 네트워크/방화벽 허용이 필요할 수 있습니다. 앱은 방화벽을 자동 변경하지 않습니다. 코드 서명·Apple 공증은 하지 않았으므로 관리 기기 정책에 따라 실행이 제한될 수 있습니다.

Mac 실행 권한 오류는 해당 폴더의 터미널에서 `chmod +x FileShare start-macos.command` 후 `./start-macos.command`로 실행하세요.

## 파일 탐색기

- 하위 폴더 탐색, 현재 폴더 이름 검색, 새 폴더 만들기
- **작업 → 복사/이동** 선택 → 대상 폴더로 이동 → **여기에 붙여넣기**
- **작업 → 이름 변경/삭제**: 폴더도 처리합니다. 삭제는 휴지통을 거치지 않는 **영구 삭제**이며 화면에서 재확인합니다.
- 대소문자만 바꾸는 이름 변경도 지원합니다. 짧은 파일 잠금은 재시도하며, 다운로드·미리보기 또는 다른 프로그램이 계속 사용 중이면 종료 후 다시 시도하라는 메시지를 표시합니다.
- 복사·이동·이름 변경 시 기존 이름과 충돌하면 거부합니다. 업로드는 `파일 (1).확장자`처럼 이름을 붙여 기존 파일을 보존합니다.
- **폴더 ZIP**: 현재 폴더를 ZIP64 지원 스트리밍 ZIP으로 받습니다. 영상 등을 빠르게 묶기 위해 무압축 ZIP을 사용합니다. ZIP 다운로드는 이어받기를 지원하지 않습니다. 초대형 파일은 개별 다운로드를 권장합니다.
- JPEG/PNG 썸네일, 사진·영상·음악 **열기**. 코덱 지원은 브라우저에 따릅니다. 썸네일은 20MiB/800만 픽셀 이하 JPEG·PNG만 생성합니다. 큰 이미지·HEIC는 아이콘과 ‘열기’를 제공합니다.
- 심볼릭 링크·Windows 정션은 탐색·작업에서 제외합니다. Go `os.Root`로 공유 폴더 경계를 제한합니다. 인증 설정 폴더를 포함하는 상위 경로는 공유할 수 없습니다.

모든 로그인 기기는 같은 공유 폴더에 읽기·쓰기·삭제 권한을 가집니다. 0.1에는 계정별 권한, 공개 링크, 텍스트 편집, 대역폭 제한, FTP/WebDAV/SMB 서버가 없습니다.

## iPhone 파일 앱·사진 앱

- **파일 선택**: iOS 선택기의 ‘둘러보기’로 나의 iPhone·iCloud Drive 등에 접근합니다. iCloud 파일은 먼저 기기에 내려받으면 안정적입니다.
- **사진·동영상 선택**: 보관함에서 여러 항목을 선택합니다. iOS의 준비·변환 시간은 업로드 진행률에 포함되지 않습니다. 원본 형식이 중요하면 선택 옵션의 ‘현재’를 쓰거나 파일 앱으로 내보낸 원본을 선택하세요.
- **다운로드**: Safari 다운로드를 통해 파일 앱에 저장합니다. 저장 폴더는 Safari 설정에 따릅니다.
- **사진 앱 저장**: 미디어 ‘열기’ 후 Safari 공유 메뉴의 ‘이미지 저장/비디오 저장’, 또는 파일 앱의 다운로드 항목 공유를 이용하세요. iOS·형식·코덱에 따라 메뉴가 없을 수 있습니다. 웹사이트가 사진 보관함에 직접 쓸 수는 없습니다.
- Android Chrome은 시스템 파일/사진 선택기와 브라우저 다운로드를 사용합니다.

## 20GB 이상 대용량

- 파일당 최대 **1TiB**, **16MiB 분할 업로드**. 전체 파일을 메모리에 올리지 않고 디스크에 씁니다. 다운로드는 HTTP Range를 지원합니다.
- **일시정지 → 이어 올리기** 지원. 브라우저나 서버가 종료되면 재접속 후 같은 원본을 **같은 대상 폴더에서 다시 선택**하세요. 이름·크기·수정 시각·앞/중간/뒤 샘플 지문이 같으면 이어 올립니다. 샘플 지문은 전체 파일 해시 검증을 대신하지 않습니다.
- iOS 사진 선택기가 재변환하거나 수정 시각을 바꾸면 새 파일로 인식할 수 있습니다. 큰 원본은 파일 앱에서 선택하는 것이 안정적입니다.
- 전송 중에는 휴대폰 화면과 브라우저를 전면에 유지하세요. iOS 잠금·백그라운드 작업은 중단될 수 있습니다. HTTP에서는 Wake Lock을 보장할 수 없습니다.
- PC는 전원에 연결하고 절전을 해제하세요. Mac 실행기는 `caffeinate -i`로 유휴 절전을 억제합니다. Windows 전원 설정은 자동 변경하지 않습니다.
- 임시 업로드 후 공유 폴더에 완성 파일을 게시하므로 **같은 드라이브라면 파일 크기의 약 2배 여유 공간**을 권장합니다. 서로 다른 드라이브면 각 드라이브에 파일 크기만큼 필요합니다. 100% 이후 최종 저장 시간이 걸릴 수 있습니다.
- FAT32는 4GB 초과 파일을 저장하지 못합니다. NTFS/APFS/exFAT 등을 사용하세요. 휴대폰 저장 공간도 충분해야 합니다.
- 실제 자동 이어받기는 브라우저 다운로드 관리자에 달려 있습니다. 서버는 Range 요청을 처리합니다.

## 데이터와 설정

기본 공유 폴더는 실행 파일 옆 `data/shared`입니다. 지정한 폴더의 파일은 기존 이름 그대로 보이고 업로드도 선택한 하위 폴더에 저장됩니다. PC에서 직접 넣은 파일도 새로고침하면 표시됩니다.

실행 파일 옆 **`FileShare.ini`**에 공유 폴더·포트·비밀번호 해시·로그인 서명 키를 저장합니다. 기존 `data/settings.json`은 자동으로 이전합니다. INI에는 인증 정보가 포함되므로 공유하지 마세요. 포트 변경은 서버를 종료한 뒤 다시 실행하면 적용됩니다.

비밀번호를 잊었다면 Windows 트레이의 **설정**에서 새 비밀번호를 지정하세요. INI를 직접 편집할 때는 서버를 먼저 종료하세요. `[server]`의 `SharedFolder`, `Port`를 수정할 수 있고, `[security]`에 `Password = 새비밀번호`를 추가하면 다음 시작 시 해시로 변환하고 평문 항목을 제거합니다. 경로는 `C:/Shared`처럼 입력하거나 기존 이스케이프 형식을 유지하세요.

`data/uploads`는 임시 파일과 재개 정보입니다. 중단된 전송은 자동 삭제하지 않습니다. 서버를 중지하고 불필요한 `data/uploads/<id>`를 지우면 공간을 회수할 수 있지만 해당 전송은 재개할 수 없습니다.

| 환경 변수 | 기본값 | 의미 |
|---|---|---|
| `PORT` | INI 또는 `8787` | 서버 포트 재정의 |
| `FILESHARE_DATA` | 실행 파일 옆 `data` | 비공개 설정/임시 저장 절대 경로 |
| `FILESHARE_ROOT` | 저장된 설정 또는 `data/shared` | 공유 경로 재정의 |
| `FILESHARE_PASSWORD` | 없음 | 설정 파일이 없을 때만 초기 비밀번호 지정 |
| `FILESHARE_CONFIG` | 실행 파일 옆 `FileShare.ini` | 설정 파일 경로 재정의 |
| `FILESHARE_NO_TRAY` | 없음 | `1`이면 Windows 트레이 없이 서버 실행 |
| `FILESHARE_NO_BROWSER` | 없음 | `1`이면 시작 시 브라우저 자동 열기 비활성화 |

HTTP는 암호화되지 않습니다. 신뢰하는 Wi-Fi 전용이며 공용 Wi-Fi·인터넷 포트포워딩 용도가 아닙니다. 공유기·방화벽 설정은 자동 변경하지 않습니다.

## 연결 문제

실제 Wi-Fi/LAN 주소를 쓰세요. VPN·가상 어댑터 주소는 휴대폰에서 접근되지 않을 수 있습니다. 게스트 Wi-Fi, AP isolation/클라이언트 격리, VPN, 방화벽, PC 절전을 확인하세요. 포트가 사용 중이면 기존 서버를 종료하거나 `PORT`를 변경하세요.

## 개발과 검증

Go 1.25 이상: `go run .`, `go test ./...`, `go vet ./...`. 릴리스는 Go 1.27.3으로 빌드합니다. `go run ./cmd/package`는 Windows x64/ARM64, macOS Intel/Apple Silicon 패키지와 SHA-256 체크섬을 만듭니다.

HTTP 통합 테스트에는 개발용 Node.js 22 이상을 사용합니다. `go build -o .local/fileshare-test.exe .` (Windows) 또는 `go build -o .local/fileshare-test .` (Mac/Linux) 후 `npm test`. 사용자 실행에는 Node.js가 필요 없습니다.

`npm run test:large`는 실제 **21GiB+123바이트 업로드 → 5GiB에서 서버 재시작·재개 → 전량 다운로드 → SHA-256 비교**를 수행합니다. 임시 디스크에 약 44GiB 여유가 필요합니다. 결과는 `release/large-file-test.json`, 상세 범위는 [검증 보고서](release/VALIDATION.md)에 기록합니다.

기능 참고: [HFS](https://github.com/rejetto/hfs), [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser), [Copyparty](https://github.com/9001/copyparty). 해당 프로그램들의 코드를 포함하거나 포크하지 않았습니다.
